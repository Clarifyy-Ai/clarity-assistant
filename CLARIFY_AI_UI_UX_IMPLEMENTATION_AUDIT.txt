PART 0 — EXECUTIVE SUMMARY & CROSS-CUTTING FINDINGS
================================================================================

0.1 PRODUCT UX IN ONE PARAGRAPH
-------------------------------
Career Pilot is a practice-first interview coaching product with a second product
line for Indian government/competitive exam MCQ tests. Web users live inside an
AppShell (sidebar + top bar + mobile bottom nav). The core practice experience
is a floating dark-glass Overlay (hints, chat, transcript, stealth controls)
launched from Practice Coach or Mock Interview. Marketing, Auth, Onboarding,
Admin, Overlay, and Timed Test Session each use a different chrome — five visual
"worlds" users move between.

0.2 HEADLINE UI/UX VERDICT
--------------------------
Strengths: real design tokens (light/dark/stealth), shadcn/Radix foundation,
shared PageHeader / EmptyState / InlineErrorRetry on many pages, strong Practice
Coach / Overlay depth, command palette, compliance messaging, reduced-motion
support.

Weaknesses: pattern fragmentation. Dual Button/Card systems, mixed Modal vs
Dialog, emoji in chrome/tabs, naming collisions (Practice Coach / Live /
Overlay / Rehearsal; Question Bank vs Answer Bank), duplicate STAR builders,
Settings preference sprawl, dual mobile navigation (hamburger sidebar + bottom
nav), and uneven adoption of empty/error/loading patterns.

0.3 FIVE CHROME WORLDS
----------------------
  1. MarketingLayout ........ public marketing + help/blog/legal
  2. Auth split-panel ....... Login / Signup / VerifyEmail (ResetPassword differs)
  3. AppShell ............... main product (sidebar / topbar / mobile nav)
  4. Overlay / full-screen .. Practice Coach overlay, LiveOverlay route,
                              Mock Test timed session (no AppShell)
  5. AdminLayout ............ standalone red-accent ops shell

0.4 CROSS-CUTTING INCONSISTENCIES
---------------------------------
  - Page wrappers: some use PageHeader + breadcrumbs; Dashboard/Scorecard/Live
    active/SharedDebrief diverge.
  - Nested PageContent: AppShell already wraps Outlet in PageContent; some pages
    wrap again.
  - Empty/error: EmptyState + InlineErrorRetry common; Blog, Interviews list,
    AnswerDetail, AuthCallback invent their own.
  - Forms: mix of shared Input, raw <input>/<textarea>, native date/select,
    shadcn Select.
  - Booleans: Switch vs Radix Toggle (often miswired with checked/onChange) vs
    chip/aria-pressed tiles.
  - Charts: CSS bar charts on Analytics/Usage vs Recharts on mock-test Analytics.
  - Naming: stealth maps still say "Live Co-Pilot" while product uses "Practice
    Coach"; Behavioural vs Behavioral spelling drift.
  - STAR: PrepLab hub embeds one STAR builder; /app/prep/star-builder is another.
  - Answer Bank detail route exists but list does not link to it.
  - Hardcoded violet-* utility classes in places bypass accent/stealth tokens.
  - Emoji used as UI chrome (onboarding tiles, Prep tabs, Analytics tabs,
    CookieConsent, Interview Day CTA).

--------------------------------------------------------------------------------
FEATURE: Design System (tokens, theme, component libraries)
--------------------------------------------------------------------------------
Feature name ............. Design System & Theme
Purpose .................. Visual language, light/dark/stealth, shared primitives
Current UI components ....
  - Tokens: src/index.css CSS variables (background, primary indigo ~239 84% 67%,
    accent cyan, destructive, muted, sidebar, chart-1..5, overlay glass vars)
  - Tailwind: darkMode class; brand.50–950; status success/warning/danger
  - Typography: Inter (sans), JetBrains Mono / Fira Code (mono)
  - Radius: --radius 0.625rem; density via --spacing-scale
  - Motion: --motion-fast/base/slow; prefers-reduced-motion override
  - Custom branded: Button, Card, Input, Modal, Tabs, Badge, ProgressBar,
    Spinner, ThemeToggle, Toggle, DataTable, SkeletonLoader
  - shadcn/Radix: dialog, alert-dialog, sheet, select, switch, command, dropdown,
    accordion, toast/sonner, skeleton, table, form, slider, checkbox, radio,
    tooltip, breadcrumb, sidebar, etc.
  - Appearance prefs: accent (violet/blue/emerald/rose/amber/cyan), font size
    (14/16/18), density (compact/default/comfortable)
Current UX flow .......... ThemeToggle / Settings Appearance → uiStore +
                           themeStore → html.dark + data-theme + data-stealth
Navigation flow .......... Global (not a page)
User interactions ........ Theme cycle, accent/density save, Discrete/Stealth
Design patterns .......... Semantic HSL tokens; overlay always-dark glass;
                           Stealth remaps primary to blue and nav labels/icons
Mobile responsiveness .... Density + font size scale; safe-top/safe-bottom utils
Accessibility ............ focus-visible rings; reduced-motion; skip links in
                           AppShell + MarketingLayout
UI/UX issues ............. Dual Button/Card APIs; Modal vs Dialog; Toggle misuse;
                           hardcoded violet utilities; unused drawer/popover
                           consumers; emoji outside design system
Suggestions .............. Single Button/Card/Modal kit; ban emoji in chrome;
                           codemod violet-* → semantic tokens; one Switch for
                           booleans; deprecate unused primitives or adopt them
Priority ................. High
