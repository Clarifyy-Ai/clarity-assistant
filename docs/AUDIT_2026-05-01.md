## 1. Overlay system

### Fixed in this audit
| Issue | Resolution |
|---|---|
| `/app/live` rendered both the 2-panel page **and** the floating overlay | `LiveRehearsal.tsx` is now overlay-only (mirrors `LiveOverlay.tsx`). Setup wizard → `<OverlayWindow />` only. |
| Two `OverlayWindow.tsx` files (one stub) | Deleted `src/components/live/OverlayWindow.tsx` (30-line stub). |
| `#clarify-overlay-root` did not exist in `index.html` → dynamic creation warning every load | Added the `<div id="clarify-overlay-root">` to `index.html` and seeded it in `main.tsx`. |
| Overlay buttons silent on `LiveRehearsal` (`onGenerate`, `onStartSession`, `onSetupNewSession` were not passed) | All seven overlay props now wired. |
| `is_visible` defaulted to false; LiveRehearsal never called `showOverlay()` | Active-phase effect calls `useOverlayStore.getState().showOverlay()`. |
| No way to recover overlay if user accidentally hides it (Ctrl+Shift+H is unreliable across browsers) | Floating "Show Overlay" pill renders bottom-right when `isActive && !isVisible`. |

### Verified working
- Portal mount at z-index `2147483647` (top-most layer).
- Drag handle, resize handles, peek mode, stealth opacity fade.
- Toolbar actions: Mic toggle, System Audio toggle, AI Help (Generate), Screen capture, Chat, More menu (stealth/auto-gen/hint style/model picker/panic).
- Hotkeys: Ctrl+Shift+H (toggle), Ctrl+Shift+S (stealth), Ctrl+Shift+P (panic), Ctrl+Shift+M (mute), Ctrl+1-4 (snap corner).
- Mock Interview (`/app/mock/session`) keeps its panel UI by design — overlay is opt-in via hotkey there.
