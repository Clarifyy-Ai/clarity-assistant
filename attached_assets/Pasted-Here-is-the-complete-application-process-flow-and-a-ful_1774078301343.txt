# Clarity Assistant — Complete Build Guide

## Application Process Flow

The entire application operates across **5 runtime layers** that must work in concert:

```
User Speaks / Types
       ↓
[Audio Layer] — Mic capture → Deepgram WebSocket → Transcript
       ↓
[AI Layer] — Transcript + Context → Model Router → Claude/GPT/Gemini
       ↓
[Overlay Layer] — Streamed answer → Stealth UI component (CSS: display:none from capture)
       ↓
[Analytics Layer] — Session data → Supabase → Dashboard
       ↓
[Billing Layer] — Credit deduction → Stripe → Balance update
```

## Phase 2 — Stealth Overlay System *(Core Differentiator)*

This is the most technically complex module. The stealth effect is achieved via CSS `mix-blend-mode` + `pointer-events: none` + Electron's `setContentProtection(true)` (for desktop) or a browser-extension approach for web. [ctrlpotato](https://www.ctrlpotato.com)

### 2.1 Overlay Architecture
- [ ] Create `OverlayManager` component as a React Portal rendered outside `#root`
- [ ] Apply `position: fixed`, `z-index: 9999`, `pointer-events: none` base styles
- [ ] Implement CSS class `stealth-mode` that toggles `opacity: 0` + `-webkit-user-select: none`
- [ ] Use `getDisplayMedia` detection: listen for `visibilitychange` + `document.hidden` to auto-hide

### 2.2 Stealth CSS Layer (Web-based approach)
```css
.stealth-overlay {
  mix-blend-mode: difference;
  isolation: isolate;
  -webkit-app-region: no-drag;
  pointer-events: none;
  /* Prevents inclusion in screen capture pixel buffer in some browsers */
  contain: strict;
}
```
- [ ] Test invisibility against Chrome tab capture, OBS window capture, Zoom screen share
- [ ] Implement `useScreenCaptureDetection` hook using `navigator.mediaDevices.addEventListener('devicechange')`
- [ ] Add panic hotkey (`Ctrl+Shift+H`) — wires to `overlayStore.toggleVisibility()`
- [ ] Build `WindowVisibilityManager` service with debounced show/hide

### 2.3 Overlay UI Components
- [ ] `AnswerOverlay` — streaming AI answer display, positioned bottom-right
- [ ] `TranscriptOverlay` — live transcript ticker at top
- [ ] `HintBubble` — compact hint card triggered by hotkey
- [ ] `SessionTimer` — floating clock
- [ ] `NetworkMonitor` — connection quality badge (WebRTC stats API)
- [ ] `PanicButton` — floating red dot, click = hide all overlays

## Phase 3 — Audio & Transcription Pipeline

Real-time transcription uses Deepgram's WebSocket API with Nova-3 model for low-latency results. [deepgram](https://deepgram.com/learn/build-a-real-time-transcription-app-with-react-and-deepgram)

### 3.1 Audio Capture
- [ ] `useAudioCapture` hook — wraps `getUserMedia` with permission error handling
- [ ] `useSystemAudio` hook — uses `getDisplayMedia({ audio: true })` for system audio capture
- [ ] `AudioMixer` service — merge microphone + system audio streams into one `MediaStream`
- [ ] VAD (Voice Activity Detection) — use `AudioWorkletProcessor` to detect silence gaps > 2s

### 3.2 Deepgram Integration
- [ ] Create `DeepgramService` class wrapping WebSocket to `wss://api.deepgram.com/v1/listen`
- [ ] Configure: `model=nova-3`, `interim_results=true`, `punctuate=true`, `diarize=true`, `filler_words=true`
- [ ] Implement connection lifecycle: open → stream → error recovery → close
- [ ] Parse `SpeakerLabel` from diarization response for interviewer vs. candidate separation
- [ ] Build `TranscriptBuffer` — assembles interim + final results with timestamps

### 3.3 Speech Analytics
- [ ] `FillerWordDetector` — regex scan on transcript chunks: `\b(um|uh|like|you know|basically)\b`
- [ ] `WPMCalculator` — rolling 60-second window: `wordCount / elapsedMinutes`
- [ ] `SilenceDetector` — track gaps > 3s in transcript timestamps
- [ ] `SentimentAnalyzer` — call Claude/Gemini with transcript chunk for real-time emotional tone scoring
- [ ] Persist all analytics per-session to `analytics` table

## Phase 4 — AI Integration & Model Router

### 4.1 Model Router (Supabase Edge Function)
- [ ] Create `supabase/functions/ai-router/index.ts`
- [ ] Input schema: `{ question, context, task_type, preferred_model, user_tier }`
- [ ] Task types: `answer_generation`, `hint_generation`, `code_review`, `star_builder`, `sentiment`, `feedback`
- [ ] Routing logic:
  - Code tasks → GPT-4o (best code reasoning)
  - STAR/behavioral → Claude 3.5 Sonnet (best long-form)
  - Quick hints → Gemini Flash (fastest, cheapest)
  - BYOK users → route to their configured key
- [ ] Implement streaming response via `ReadableStream` → SSE back to client
- [ ] Add retry logic with exponential backoff on rate limit (429)
- [ ] Log token usage to `credits_ledger`

### 4.2 Answer Generation Pipeline
```
Transcript chunk arrives
    → DeduplicateQuestion (fuzzy match last 3 questions)
    → EnrichContext (attach resume snippet + JD snippet)
    → RouteToModel
    → StreamAnswer to AnswerOverlay
    → SaveAnswer to answer_bank
```
- [ ] `useAnswerGeneration` hook — manages streaming state, cancels on new question
- [ ] `QuestionDeduplicator` — prevent re-answering same question within 30s
- [ ] `ContextBuilder` — attach relevant resume bullet + JD requirement to every prompt
- [ ] Answer streaming via `EventSource` or `fetch` with `ReadableStream` reader

### 4.3 AI Feature Edge Functions
- [ ] `hint-generator` — returns 3-bullet hint without full answer
- [ ] `star-builder` — takes raw answer text, structures into Situation/Task/Action/Result
- [ ] `code-analyzer` — accepts code string, returns complexity analysis + improvement suggestions
- [ ] `rephraser` — rewrites answer for clarity, confidence, conciseness
- [ ] `company-researcher` — calls Perplexity/Gemini with company name for culture/values summary
- [ ] `feedback-generator` — end-of-session full scorecard generation

## Phase 9 — Security & Privacy

- [ ] All API keys stored in Supabase Vault (never in client)
- [ ] BYOK keys encrypted with `pgp_sym_encrypt` before storage
- [ ] RLS policies audit: each table has `auth.uid() = user_id` policy
- [ ] Rate limiting on Edge Functions: 60 requests/minute per user
- [ ] `AccountDeletion` flow — delete all user data + Storage files + Stripe subscription cancel
- [ ] GDPR data export: generate JSON dump of all user data on request
- [ ] CSP headers configured in Vite build
- [ ] Sentry DSN configured — capture frontend errors with user context (anonymized)

## Build Order (Recommended Sprint Sequence)

| Sprint | Focus | Deliverable |
|--------|-------|-------------|
| **1** | Auth + DB Schema | Login, signup, RLS working |
| **2** | Overlay + Hotkeys | Stealth overlay invisible in Zoom |
| **3** | Audio + Deepgram | Live transcript on screen |
| **4** | AI Router + Streaming | Answer appears in overlay |
| **5** | Prep Tools | STAR, Answer Bank, Mock sessions |
| **6** | Analytics + Gamification | Dashboard, XP, streaks |
| **7** | Billing + Credits | Stripe checkout, credit deduction |
| **8** | Docs + Security | Resume upload, BYOK, GDPR |
| **9** | Testing + QA | All test suites passing |
| **10** | Production Deploy | Live on Lovable |

The most critical path items are **Sprints 1–4** — once you have auth → overlay → audio → AI answer working end-to-end, you have a shippable MVP. The stealth overlay is your core technical moat, so validate it against Zoom, Google Meet, and OBS before building any other feature on top of it. [interviewbee](https://interviewbee.ai)
